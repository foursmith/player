# 原生迁移技术方案与验收

范围：以 `../web/` 为唯一行为和视觉参考，迁移已有功能，不增加产品功能。UI 使用 MyGo 原生绘制；FFmpeg 负责媒体，SDL3 负责音频，平台 GPU 负责投影。原有三语、图标、海面背景、设置默认值、快捷键、投影与人像居中策略沿用。

控件材质与弹层几何按浏览器实际计算样式对照，见 [UI_PARITY.md](UI_PARITY.md)。

## 所有权

- `main.go`、各原生视图：主线程拥有交互、设置、目录、相机状态。
- `internal/media`：单一工作线程拥有解码器、音频时钟和有界视频队列，UI 只取不可变状态及引用计数帧。音频预读独立于视频解码提前量；跨越 MP4 交错块时暂存压缩视频包（达到 32 MiB 停止预读），定位时同时清空压缩包、解码帧和音频。呈现前重新读取音频时钟，丢弃已被更新帧取代的画面；取消检查覆盖压缩包、解码、等待硬件帧和定位循环，连续切换时跳过已取消的打开请求。
- macOS 的 H.264/HEVC 播放：FFmpeg 解封装压缩包，`internal/media/video_decoder.c` 将有 avcC/hvcC 参数集的包异步提交给系统 VideoToolbox，通常维持 8 个在途画面，重排序时上限 32 个。按 PTS 排序并以 DTS 判断未来包边界，输出引用计数 CVPixelBuffer；回调只交付解码结果，不操作 UI 或播放器状态。准确定位、EOF 和关闭均处理在途帧；不支持的输入或硬件会话创建失败时沿用 FFmpeg 解码，导出仍使用独立 FFmpeg 解码器。
- `internal/video`：七种投影和多视口；macOS 直接采样 CoreVideo 纹理，非 macOS 暂用上传纹理。
- `internal/detection`、`internal/tracking`：推理与纯算法分离；请求带媒体代次和追踪代次，丢弃失效结果。
- `internal/library`、`internal/subtitle`：目录、排序、匹配与字幕解析为独立数据模块。`subtitles.go` 在后台完成自动查找、本地/远程读取与解析；每次选择视频或手动加载字幕会取消上一请求，过期结果不能覆盖新视频。
- `internal/exporter`：独立解码、投影和编码会话，不共享播放解码器。复用相同字幕与追踪算法。

## 验证原则

算法、媒体、协议使用源文件旁的单元测试；执行 race、Go/MyGo vet 及正式构建。不添加 UI 自动化或 e2e 测试。构建成功不能作为 UI 等价或其他平台验证的证据。

## 已迁移的功能

- 海面空状态、原始 Logo/Phosphor 图标、三语、设置与说明文案。
- 文件与文件夹导入、文件拖放、文件夹优先的自然排序、目录树、字幕一对一匹配；文件夹范围内顺序播放和循环。
- 播放、暂停、音轨、保留音调的倍速、音量、准确定位、A/B 循环与播放历史。
- 七种投影、半球边界约束、多视口、质量倍率与播放帧率；相机交互独立于播放帧率。
- 旋转、深度缩放、快捷键、控制条隐藏、弹层、全屏和原生置顶 PiP 窗口。
- FSVR cookie 认证、远程目录懒加载、远程字幕和 DLNA 扫描。原先浏览器的服务源通过 `--server` 显式传入，不在原生进程内增加一个服务器。
- A/B MP4、WebM、动态照片导出，保留音轨、投影、字幕及人像居中；导出帧有界保留用于预览。
- 原有短距/全距模型、连续目标选择、恢复扫描、运动预测、自适应推理、调试采样与录制/复制日志。

## 已完成的验证

- `just check`：Go vet、MyGo vet、gofmt。
- `just test`：全量 race 单元测试，涵盖状态文件、字幕解析、文件树、字幕匹配、认证协议、解码/音频/定位/结束、投影、追踪与调度。
- 两个原始模型均执行空图负例与 MediaPipe 上游人像正例推理。
- 七种 Metal 投影的离屏回读与 CPU 相机坐标计算对照，检查上下方向、立体眼裁剪和遮罩；该检查不创建 UI 窗口。
- MP4、WebM、动态照片执行真实编码，检查音轨、视频尺寸及字幕合成路径。
- 远程输入阻塞时，播放器关闭会取消 FFmpeg I/O，不等待读取超时。
- 半秒交错块的合成 MP4 可持续播放至结束；音频预读至 EOF 后定位不会残留旧压缩包或丢失视频帧。
- 播放解码器的 H.264 B 帧顺序、EOF 延迟帧和定位；macOS HEVC 8/10-bit、8 个 B 帧、原生纹理与 RGBA 回读，以及定位/关闭后仍被渲染或检测持有的帧引用。
- 缓存仍有压缩包和硬件帧时取消会中止解码；阻塞网络打开期间连续选择视频，最终选择无需等待旧请求的超时。
- 定位先发布等待新帧的状态，人脸居中在此期间停止；新帧就绪后恢复检测，旧推理结果不能恢复旧目标或覆盖新请求。
- 本机 macOS arm64 构建、动态库递归收集、重定位及临时签名。
- 原生空状态和设置曾进行实际截图检查，并查看 `web/` 的同一布局作为参照。随后依据原版修正了矩阵、开关、说明截断、图标和若干控件。

## 验收边界

实现迁移与最终视觉验收分别记录。当前没有证据可以把所有界面、窗口尺寸、焦点路径及播放场景声明为完全一致。完整人工验收仍需覆盖窄窗口、PiP、所有弹层、字幕、导出状态及远程/DLNA 实际设备。未运行 UI 自动化或 e2e 测试。

Windows/Linux 具有原生 UI、FFmpeg 解码与打包代码，但未在对应系统编译或实机验证。当前它们的解码帧通过 RGBA 上传后投影；macOS 的 CVPixelBuffer 到 Metal 路径直接共享硬件纹理，不能将本机的性能结论套用于其他系统。HDR、色彩管理和高分辨率长时间播放仍需代表性媒体实测。

本机 M4 对一段 8192×4096、59.94 fps、约 65.6 Mbps 的 HEVC Main 8-bit 文件，原来的逐帧等待硬解路径抽样约 49–52 fps；异步播放路径连续解码 180 帧约 177–181 fps，全部保留原生纹理。使用 CoreAudio 输出（静音）进行 35 秒无界面播放，视频推进 34.985 秒；按呈现时音频时钟与视频 PTS 的差统计，P95 为 15.65 ms，最大 19.24 ms。交替切换该文件和小视频首帧耗时 74–174 ms，定位到 600.123 秒耗时 217 ms，连续快速选择 17 次后最后一次恢复到历史位置耗时 244 ms。独立 SDL dummy 测量的偏差最大 16.7 ms。这些是媒体内核测量，未包含显示器扫描、实际扬声器延迟或完整 UI/人脸推理负载，不代表全部 8K60 场景验收通过。该文件约 0.47 秒的音频预读死锁也已修复。
