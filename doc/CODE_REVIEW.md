# app 代码审查与性能整理

审查日期：2026-11-05。基线：`5da060c`。依赖保持 Go 1.27.3、MyGo v0.7.4；实际验证平台为 macOS arm64 / Apple M4。

## 范围

检查了原生窗口与 UI、持久化、播放列表、字幕、远程协议、FFmpeg/SDL 播放内核、Metal/通用投影、人脸检测与追踪、导出、资源和打包脚本。修改集中在能从现有代码路径确认的问题；没有升级框架或改写媒体架构。

MyGo 用法对照本项目固定版本的 `docs/ui/views.md`、`docs/ui/list.md`、`ui/bitmap.go` 对应实现及窗口 API；在线说明见 [Views](https://mygo.egoist.dev/docs/ui/views)、[List](https://mygo.egoist.dev/docs/ui/list)。

## 已修复的问题

| 问题 | 处理 |
| --- | --- |
| 播放列表每次重绘都构造、自然排序完整目录树，并创建所有展开行 | 缓存目录树与展开行，仅在导入、清空、远程加载或展开状态变化时重建；使用有稳定 Key 的 `ui.List`，只构建可见行及少量预备行。保留原行高、缩进、单击播放和文件夹懒加载行为。 |
| 列表顶部操作可能在构建列表途中清空条目 | 共用图标按钮和列表行使用 `OnClick`，让集合修改在构建结束后执行。跨构建控件身份继续使用 `ui.Handle`。 |
| 自动保存、音量和设置变更在 UI 线程序列化并写磁盘 | 单个后台 writer 串行保存独立快照，合并尚未写入的旧请求；退出时等待最后一次保存。退出后的关闭回调不再提交保存。沿用原子替换、权限和配置格式。 |
| 空播放器、暂停及播放结束后仍每 4ms 唤醒 | 只有解码器需要推进时启用 ticker，其余时间等待命令；定位、继续播放和重新打开会恢复调度。 |
| 暂停画面随控件重绘反复提交同一视频投影 | 按帧 ID、投影、尺寸、代次及显示倍率判断是否重新提交；窗口显示、恢复或重新获得焦点时重新呈现，PiP 重建时清空呈现缓存。 |
| 推理每次分配输入、输出及 C 错误缓冲区，输入还被重复初始化 | 缓冲区归检测器所属 worker 复用，逐像素写入覆盖全部输入；复用固定尺寸 Metal 捕获纹理，尺寸变化时重新分配。 |
| NMS 依赖种子框的 self-IoU 将它移出队列，零面积框会使循环无法前进 | 种子框无条件出队，再合并其余候选框。 |
| 导出将异步的 `Window.Update` 当作同步初始化；保存对话框期间切换视频可能继续旧任务 | 每次导出拥有独立 context、身份和预览槽；在主线程确认任务仍有效后启动编码。切换、清空本地播放和退出会取消旧任务；旧回调不能修改当前任务。预览槽关闭后会释放迟到帧。 |
| 导出每帧都向 UI 投递相同整数百分比 | 只在百分比变化时投递进度，避免编码速度较快时堆积 UI 更新。 |
| 远程请求不随退出取消，后台直接读取可变客户端字段 | 捕获客户端、窗口和连接 context；替换连接及退出时取消请求，回调验证连接仍有效。忽略响应内容时有界读取响应体，以便复用 HTTP 连接。 |
| 自动查找同目录字幕时重新导入全部媒体、读取元信息并执行全目录字幕匹配 | 仅筛选字幕文件名；单视频匹配采用一次扫描，保留贪心匹配的评分及平分顺序。 |
| 字幕按开始时间排序，却按不保证单调的结束时间二分查找 | 解析时建立最大结束时间的前缀索引，维持对数查找；重叠时选择开始顺序中的第一条有效字幕。直接提供的 Cue 切片也可查询。拒绝非有限时间戳。 |

另外移除了未使用的第二套解码中断入口、导出自定义合成钩子、重复的依赖环境判断、重复设置 dylib ID，以及相机约束中的重复覆盖计算；静态 UI 主题改为复用。保留现有字幕合成、基于 context 的 FFmpeg 取消、原生纹理和系统窗口路径。

## 性能对照

使用 `-benchtime=300ms -count=3`，非 race 模式，三次顺序采样。推理基线通过 Go `-overlay` 加载 `5da060c` 的 `detector.go`，其余基准代码和模型相同。

| 场景 | 原路径 | 整理后 |
| --- | --- | --- |
| 10,000 条播放列表模型重建 | 每次约 32–33ms；稳定采样约 3.40MB / 32 次分配 | 数据不变时复用缓存，0B / 0 次分配；库发生变化仍需一次重建 |
| 短距模型，320×320 空图，每次检测的 Go 分配 | 259,072B / 4 次 | 0B / 0 次 |
| 全距模型，同一输入 | 600,320B / 4 次 | 0B / 0 次 |

推理耗时仍主要来自预处理及 LiteRT：短距约 1.3–1.5ms，全距约 4.2ms。本次不根据这些小幅波动宣称推理吞吐提升。零分配结论仅适用于该无检测结果的基准；有人脸时仍需构造结果和执行 NMS。列表模型基准也不包含完整 UI 绘制、GPU 或显示器扫描。

复跑当前基准：

```sh
./scripts/native-env go test . -run '^$' -bench BenchmarkPlaylistModel -benchmem -benchtime=300ms -count=3
./scripts/native-env go test ./internal/detection -run '^$' -bench BenchmarkBundledFaceModels -benchmem -benchtime=300ms -count=3
```

## 验证

- `just check`：Go vet、MyGo vet、gofmt 全部通过。
- `just test`：全量 race 测试通过，包含两种原始人脸模型、真实解码/定位/取消、七种投影读回及真实编码。新增覆盖保存快照与最终落盘、目录模型更新、字幕发现与重叠时间、退化检测框、并发关闭预览及迟到帧释放。
- `just build build/review`：构建、21 个原生动态库打包及临时签名校验通过，产物为 `build/review/darwin-arm64/Foursmith Player.app`。
- 没有启动、重启或操作正在运行的应用，也没有执行 UI 自动化。

仍需原生窗口人工验收长列表滚动、窗口恢复、PiP、保存对话框期间切换媒体，以及真实远程/DLNA 设备；Windows/Linux 未在本次实机验证。这里的单元测试和构建结果不构成完整界面或 8K 播放性能验收。
