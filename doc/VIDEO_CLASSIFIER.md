# 轻量视频格式分类实验

本地 MobileNetV3-Small 原型一次输出普通 2D 或六种具体 VR 投影。模型通过现有 LiteRT C 运行库执行，播放器不依赖 Python 或额外模型服务。Python 仅用于生成数据、训练和导出。

当前默认启用这个实验模型：`assets/models/projection.tflite` 随应用嵌入，没有空间元数据或元数据与布局存在歧义的视频会在同一批有效抽帧上执行七分类，无需设置环境变量或安装 Python。分数不足、模型加载或推理失败时保留画面规则和文件名结果。多帧确认的清晰鱼眼圆弧优先于模型的其他类别分数，明确的手动选择优先。自动结果以类型 ID 单独保存在历史的 `AutoProjection` 字段，手动选择使用 `Projection` 和 `ProjectionManual`，两者互不覆盖。无手动覆盖时先应用自动缓存并后台复查，识别完成后更新；等待期间不把临时类型写入自动缓存。手动选择跳过自动识别，点击“重新识别”清除手动覆盖。不维护未发布算法的历史版本迁移。

双目优先、单目辅助。当前融合逻辑保护多帧稳定的左右/上下对应证据，单目 180、单目 360 或单目鱼眼预测不能覆盖它，即使 softmax 分数很高；左右 180 内部仍允许 AI 在 EQR 和鱼眼间细分。这项保护依据实际帧投票，文件名提示不等同于已确认的双目布局，也不改变证据不足时的正常单目支持。

## 模型与输入契约

- MobileNetV3-Small ImageNet 预训练骨干，2×2 平均池化、128 单元分类头，七类 softmax；先训练分类头，再小学习率微调骨干末尾层。
- 输入 `[1,224,224,3]`、float32 RGB，数值为 0–255；整帧等比放到黑色底上，双线性缩放，不做中心裁剪。
- 输出 `[1,7]`、float32 softmax，顺序固定为 `sbs_180_eqr`、`sbs_180_fe`、`mono_360_eqr`、`m_180_eqr`、`m_180_fe`、`tb_360_eqr`、`flat_2d`。
- 权重导出为 float16，输入和输出仍为 float32；当前文件 3,240,840 字节、1,603,703 个参数。
- 内置权重 SHA-256：`e2485c9edce7374505744dfac4b4cad20a8df807c7173b1bcd5f5acb94ae526f`，来自本次本地训练输出。
- 随机跨前、中、后三段抽帧，过滤黑屏/无细节帧。清晰结果通常取 3 个有效帧；不确定时继续补帧，最多 9 次、总计 12 秒。先匹配双目，再检查单目全景；普通水平视差范围为眼宽的 1/8，失败后重试 1/4，亮度相关、纹理相关和有效匹配块比例门槛不变。搜索严格限制在目标眼内。
- 常规画面投票要求至少 2 帧且三分之二一致。补帧过程中，若至少 3 帧完整匹配同一双目格式、其余帧均未能匹配且没有其他 VR 票，也确认该双目格式；未匹配本身不等同于已经确认普通 2D。
- 常规 AI 路径平均各帧七类分数，至少两帧、最高平均分不低于 0.8 且领先第二名至少 0.15 才采用。没有明确圆弧的 SBS 鱼眼预测，以及与画面规则冲突的双目投影，至少收集 9 个有效帧，避免少量近景导致投影误切。
- 补充路径仅用于原本会退回 2D 的结果：至少两帧各自达到同样的 0.8/0.15 门槛、占全部模型帧的三分之二且所有高分帧无冲突，同时至少三分之二画面有局部眼间对应（相关度 0.75、至少 2/16 块匹配），才接受该双目类别。单目不走这条补充路径，SBS 鱼眼仍要求 9 帧确认。
- EQR/鱼眼模型分数分散时，二者概率之和可作为 SBS 布局分数；同样要求 0.8/0.15 门槛，并且至少 3 帧实际达到完整的眼间匹配门槛、占画面 VR 票至少三分之二，没有其他双目投影票，才用画面规则确认的投影挽回 2D 回退。未匹配画面在此作为证据不足弃权，模型仍须明确支持该双目布局。布局分数不能单独选择 EQR/鱼眼，也不能替换已经稳定的 VR 投影。

softmax 分数未经概率校准，这些门槛不能保证正确。

通用分类器适配位于 `internal/detection/classifier.go`，与 BlazeFace 共用 LiteRT 加载器；保留独立模型实例和预处理，未改变人脸模型的输入、锚点或后处理。

## 数据与复现

Powered by [Poly Haven](https://polyhaven.com/our-api)。源全景图采用其 [CC0 资源](https://polyhaven.com/license)，下载时检查原始 MD5。40 张全景图被分为 28 张训练源图、6 张验证源图、6 张测试源图；相同场景的编号变体不允许跨数据分集。每个源图生成七类、每类 12 个方向/曝光/压缩变体，总计 3,360 张图。

投影通过三维方向到源全景图的映射生成。普通视频使用透视投影，立体样本使用近似局部视差与曝光变化。**模拟立体不是实拍的双目基线、遮挡和镜头畸变**。当前数据主要是室内外场景，不能代表全部人物视频或真实相机处理流程。真实播放记录中的视频只用于本地验证，没有上传或参与训练。

```sh
just model-env
just model-data
just model-train
just classify --model .cache/projection-model/experiment/projection.tflite /path/to/video.mp4
```

`model-env` 使用 uv 在 `.cache/projection-model/venv` 安装固定版本依赖。数据清单、缓存、训练日志、Keras/SavedModel、TFLite 和报告均在 `.cache/projection-model/`；仅选定的 TFLite 权重复制到 `assets/models/projection.tflite` 并嵌入应用。更改生成设置时使用新的 `--out` 目录；特征缓存绑定数据 SHA-256 和框架版本。

`just dev` 或构建后的应用默认使用内置模型。开发时可在启动进程前覆盖权重，或临时关闭模型作对照：

```sh
FSVR_PROJECTION_MODEL="$PWD/.cache/projection-model/experiment/projection.tflite" just dev
FSVR_PROJECTION_MODEL=off just dev
```

已经运行的进程不会获得新的 shell 环境变量。`just classify` 默认读取仓库中同一份内置权重，可以独立验证，不修改视频、文件名或播放历史。`--recent /path/to/state.json` 可只读验证指定历史文件中的最近列表。诊断输出包含模型原始类别、各类分数、每帧画面识别、画面投票、空间标签、可直接采用的 `metadata_mode`、最终融合类型 `resolved_mode`、决策来源 `reason`、逐帧高分票 `confident_frame_votes`、有效帧数和推理耗时。诊断会执行模型用于对比，但最终类型与播放器遵循相同的元数据决策。播放器日志也会记录类型、有效帧数、模型最高分和置信度是否达标，以及抽帧失败原因。

测试开关同时启用 `[playback]` 的打开、跳转请求和首帧就绪日志，包含播放 generation、目标/实际 PTS、解码器和耗时。主播放错误在普通模式中也会记录具体阶段、文件、位置和底层错误；VideoToolbox 会保留 session/submission/callback 阶段及原始 OSStatus，避免只剩通用的外部库错误。

可信空间标签在测试模式中也会执行画面和模型诊断，最终保留正常模式的标签优先级。开关不会放宽模型门槛或双目保护，不改变分类算法来迎合测试结果。关闭开关后恢复正常的历史类型读取和保存行为。

## 本次实验结果

7680×3840 H.264 Main 实例复查：VideoToolbox 初始化报错后 FFmpeg 实际仍可回退并抽到有效帧；真正让播放器停在 2D 的是完整全景 + SBS 标签被直接归为不支持的左右 360，跳过了模型。2:1 的这类组合交给画面/模型确认，保留 4:1 左右 360 等明确不支持布局的处理。抽样的 AVC/H.264 少量帧直接软件解码，HEVC 等格式保留硬件加速，避免增加原本正常的 8K HEVC 检测耗时。主播放原生会话失败后直接开软件解码器，FFmpeg 自身回退后也不再因随机定位反复选择已失败的硬解格式。该文件三轮各抽到 3 帧、无硬解报错，最终均进入左右 180 VR；其中两轮为 EQR、一轮为鱼眼。具体投影尚未人工确认，不能将进入 VR 等同于七分类已完全准确。

鱼眼漏判复查：旧默认规则要求固定圆外区域至少 94% 为黑，实际鱼眼视频的水印和边缘残留会令它失败，且判型还依赖立体相似度。`internal/projection/fisheye.go` 改为沿 128 条射线提取可见圆弧，以跨至少三个象限的圆拟合排除离群点，兼容轻微椭圆，再检查拟合精度、圆外黑区和圆内纹理。部分裁边只留下短圆弧时采用更严格的精度，避免把圆角矩形当成镜头。清晰双镜头直接识别为 SBS 180 FE，单镜头为 Mono 180 FE。

经手动确认的 8K 鱼眼样本，固定位置三帧及三轮随机检测的九帧均识别为 SBS 180 FE；另两段 EQR 和一段普通视频在三轮对照中没有被识别为鱼眼。长视频抽样也改为优先读取附近关键帧，避免为精确抽样连续解码长 GOP；重复关键帧会精确定位替换。测试覆盖水印、局部暗主体、偏心、部分裁边、圆角矩形/EQR 黑角的反例、AI 覆盖保护和重复黑色关键帧，不含 UI 自动化。

2026-11-05，macOS arm64 / Apple M4。测试集 504 张图来自 6 个未参与训练的全景场景，float16 TFLite 总准确率 **92.06%**：

| 类别 | 测试准确率 |
| --- | ---: |
| 左右 180 EQR | 88.89% |
| 左右 180 鱼眼 | 100% |
| 单目 360 EQR | 65.28% |
| 单目 180 EQR | 97.22% |
| 单目 180 鱼眼 | 100% |
| 上下 360 EQR | 100% |
| 普通 2D | 93.06% |

这些是合成投影测试成绩，尤其单目 360 EQR 与左右 180 EQR 仍明显混淆，不代表真实视频七分类准确率。四段真实视频的最高分分别为两段左右 180 EQR、两段 2D，但只有一段超过当前自动接受阈值；另一段 8K VR 在 EQR 与鱼眼之间摇摆。当前作为默认开启的试验保留置信度门槛和画面规则，需要补充按视频划分、人工确认投影的真实训练与测试数据。
