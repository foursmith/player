# Foursmith Player 原生版

Go + MyGo 开发快照 `v0.7.5-0.20261106080026-6121009b900d` 原生 UI，FFmpeg 解封装与解码，SDL3 音频输出。原生程序不嵌入浏览器，也不启动 Bun 服务。迁移工作区中的 `../web/` 保存原实现，作为界面、交互及算法对照；构建所需资源已收录本仓库，无需该目录。

```sh
brew install go just ffmpeg sdl3
just deps
just dev
just check
just test
just build
```

以上命令在本仓库根目录执行。`just build` 收集本机 FFmpeg/SDL 的动态依赖，加入 LiteRT C 运行库，再重新执行本机临时签名，并在 macOS 生成自定义 DMG。Apple Silicon 产物为 `build/darwin-arm64/Foursmith Player.app` 和 `build/darwin-arm64/foursmith-player-0.2.6-arm64.dmg`；名称、版本与文件名前缀读取 `mygo.json`，校验和写入 `build/SHA256SUMS`。正式分发仍需开发者证书签名和公证。

DMG 复用应用主页的深海背景、薄荷色调与斜体标语，两个名称底板使用透明白色叠加和顶部高光，保留 Finder 原生名称及拖入 Applications 的安装方式。`just preview-dmg` 生成 `build/dmg-preview.png`，不构建应用；背景包含 600×400 和 1200×800 两种分辨率，由 `scripts/dmg-artwork.swift` 使用系统字体和 AppKit 绘制。Finder 布局由 `assets/dmg/layout.dmg` 统一维护；修改应用名称或布局时，用 `uv run --with ds-store==1.3.1 python scripts/dmg-layout.py` 重新生成模板，普通构建无需 Python 或 Finder 自动化权限。

图标、模型和三语文案由原生项目的 `assets/` 独立维护，应用名称与版本读取 `mygo.json`。

仅在明确需要应用包时执行 `just build`，统一覆盖 `build/` 中对应平台的现有产物，不为每次修改另建测试包。日常开发使用已有开发实例及相关检查、测试；若固定目录中的应用正在运行，先处理运行占用，不另建输出目录。协作规则见 [AGENTS.md](AGENTS.md)。

macOS 使用 VideoToolbox + CVPixelBuffer + Metal，Windows 使用 D3D11VA + D3D11 + DirectComposition。两者的硬解画面都保留在 GPU 上，原生视频层绘制在 UI 下方，支持主窗口和画中画；颜色转换、2D 适配及 VR 投影均由 GPU 执行。Windows 视频层和 UI 共用 MyGo 的内容子窗口，分别占用下层和上层合成树，避免视频被内容子窗口裁掉。Windows 将解码器纹理数组中的当前画面在 GPU 内复制到可采样的 NV12/P010/P016 纹理，不执行整帧 CPU 回读或 RGBA 上传。检测先在 GPU 上生成所需的小尺寸视图，再回读给模型；缩略图仍使用独立解码器。已在 macOS arm64 验证原生应用，在 Windows amd64 运行原生 GPU 自动化测试及 8K Main10 片源性能检查。

Linux 及便携回退路径复用 FFmpeg 转换器、硬件帧回读缓冲和两张交替使用的 RGBA 图像，避免高分辨率视频逐帧分配整张图像；画面更新前保留上一张图像，主窗口与画中画各自维护缓冲，关闭视频返回首页后释放缓冲。Linux 尚未实现 VAAPI 纹理直接共享。Windows 的软件解码格式保留 RGBA 上传，原生呈现失败时保留便携回退。各转换路径遵循片源的 BT.709、BT.601、BT.2020 色彩矩阵与全/有限范围标记。FFmpeg 根据本机 CPU 自动选择视频解码线程数，硬件解码器打开失败时释放硬件状态并以软件解码器重试。

Windows D3D11 硬解使用片内线程，避免帧线程在启动和定位后增加输出延迟。精确定位时保留所有参考画面，只跳过目标前的非参考画面，目标附近恢复完整解码；H.264 与 HEVC Main10 的目标及后续画面已与完整解码逐帧对照。播放器优先发布首帧，再预读后续音频；连续拖动会在解码和音频预读循环中让出旧定位请求，直接处理最新目标。长 GOP 的参考画面仍须解码，定位延迟取决于片源和显卡。

视频画面跟随片源时间戳更新，使用屏幕原生像素比例渲染。播放中的视频与 VR 视角通过 MyGo 的绘制级刷新跟随显示器节奏，不逐帧重建界面；没有新视频帧或视角变化时复用已有画面。播放、暂停、定位和错误等状态切换立即更新界面，字幕切换按视频时间戳触发，进度轨道独立重画，播放中的进度文字按 250ms 间隔更新，调试信息按 100ms 间隔更新。暂停且无交互时停止连续刷新；画中画不再因主窗口重建而重复请求视图更新。AB 标记用于循环播放所选片段，包括将 B 设在片尾的情况。

悬停进度条可预览画面与章节，普通悬停显示附近关键帧并保持稳定；按住向上拉可展开胶片条，按源视频帧率精确定位，松开跳转，Esc 或丢失鼠标捕获取消。预览使用独立静音解码器，不改变主视频进度。内嵌章节显示为分段进度条，点击章节名可打开列表并跳转；列表支持读取容器内置章节封面，无封面时显示文字。进度条获得焦点后，左右方向键逐帧移动，Home/End 跳到起点或片尾。

构建仅支持本机平台：在 macOS、Windows 或 Linux 上运行 `just build`，统一输出到 `build/<系统>-<架构>/`。不提供交叉编译、其他平台运行库自动下载或跨架构打包流程。Windows/Linux 的播放与打包尚未通过实机验收。

Windows amd64 已运行原生自动化测试，覆盖 H.264/AAC 播放、暂停、倍速、B 帧顺序、进度定位、HEVC Main10、中文和空格路径、硬解打开失败后的软件回退及 DLNA 协议；本机 H.264 和 HEVC Main10 样本均已走 D3D11VA 硬解。D3D11 测试将 8/10 位硬解纹理的七种投影输出与 CPU 参考像素对照，并覆盖窗口缩放、清理后重播、解码与截图并发以及软件格式。测试样本编码器需要提供 `libx264` 和 `libx265`。Windows SSDP 通过 Winsock 的 IP_PKTINFO 读取请求实际进入的网卡，回复使用该网卡地址，支持多网卡。高分辨率性能仍取决于显卡、驱动和片源码率，HDR 色调映射及电视/VR 设备互通仍需验证；YUV 色彩矩阵处理不等于 HDR 色调映射。

FFmpeg、SDL3 和 LiteRT 通过 purego 动态调用。FFmpeg 绑定固定为 **FFmpeg 9** 的 ABI：avutil 61、avcodec/avformat 63、avfilter 12、swscale 10、swresample 7；加载时校验主版本。`scripts/ffmpeg-abi.py` 仅用于升级绑定时根据本机开发头文件重新生成 64 位结构体布局。

本机需要 FFmpeg 9、SDL3 和兼容的 LiteRT C 运行库。`just deps` 在 macOS arm64 下载固定版本的 LiteRT；其他系统通过 `FSVR_TFLITE_LIBRARY` 指定本机推理库，`FSVR_NATIVE_LIB_DIR` 可指定本机媒体运行库目录。Linux 打包还需要预先安装 `patchelf`，使用本机 `ldd` 收集依赖；生成包的系统库兼容范围取决于本机构建环境。

macOS 的异步 VideoToolbox 解码与 Metal 渲染同样通过 purego 调用系统框架，保留 CVPixelBuffer 零拷贝和 8/10 位 YUV 处理。日常开发与构建使用 `CGO_ENABLED=0`，无需 C 编译器或开发头文件；仅重新生成 FFmpeg ABI 时需要匹配的开发头文件和 C 编译器，竞态测试需要 Go 的 CGO 竞态运行时。`just doctor` 检查媒体依赖和 GPU。

设置、最近文件和播放历史保存在系统用户数据目录中的 `Foursmith Player/state.json`，只读取当前应用的数据目录。macOS 最近文件同时通过 MyGo 同步到系统，供 Dock 菜单显示；MyGo 在同一用户数据目录维护 `recent-documents.json`。`--data-dir` 可隔离开发配置；文件或文件夹可直接作为启动参数。本地续播和视频类型缓存以“完整路径:文件大小:修改时间”的 SHA-256 作为键，DLNA 使用设备 ID 与媒体对象 ID 的哈希，不保存明文文件名或临时播放地址；只读取当前哈希格式，不迁移旧开发版记录。最近文件列表按其用途保留完整路径；仅开启“启动时打开上次视频”时保留单独的 LastFile 路径，关闭后清除。

首页在 macOS 使用“打开…”和“视频库”两个入口，原生选择器可同时选择多个视频文件与文件夹；Windows/Linux 保留“打开文件 / 视频库 / 打开文件夹”三个入口。打开文件、文件夹或拖入视频会替换当前播放列表，并立即播放新选择；播放列表底部的“添加”只追加文件，保留当前播放或暂停状态。原生“文件”菜单提供打开、最近文件、添加、关闭视频和 DLNA 搜索。macOS 使用 ⌘O 打开文件、⇧⌘O 打开文件夹、⇧⌘A 添加文件、⌘, 打开设置；Windows/Linux 使用 Ctrl。设置使用独立窗口，左侧按播放、VR、快捷键、通用和关于分类，右侧显示所选分类；分屏布局、画面比例、人脸居中和识别设置统一放在 VR 分类中，该分类始终可用。重复打开会聚焦已有窗口，Escape 或系统关闭操作关闭设置。进度恢复适用于本地文件和 DLNA 视频；开启历史记录时，关闭视频会保存进度并停止下次启动时自动打开该文件。

首页的大鱼和品牌小光点沿用 Web 版的 18 秒互动节奏：大鱼探身，小光点退让、缩小消失，再返回。海洋背景、图标和光点动画仅在主窗口获得焦点时持续刷新；失去焦点时暂停，重新聚焦后从暂停处继续。系统开启减少动态效果时保持静态展示。

视频库可从首页、播放列表标题栏或“文件”菜单打开，使用独立窗口管理。文件夹、DLNA 设备来源和自定义合集会保存在 `state.json` 中，重启后保留；选择视频库或点击刷新时在后台重新读取内容；默认每 10 秒刷新当前打开的库，可关闭自动刷新，不在启动时扫描所有来源。可以创建空合集、将当前本地播放列表存为合集、追加文件、文件夹或收录当前播放列表，支持重命名、搜索、逐项移除以及失效文件重新定位。添加和整理视频库不会切换当前播放；本地库点击视频或“播放全部”会打开当前目录范围内的可用视频，“添加到播放列表”追加到现有列表末尾并保留当前播放。DLNA 的“播放全部”和“添加到播放列表”直接加入整个设备来源，保留目录树并复用已浏览内容，不预先扫描；展开尚未加载的目录时按需读取。文件夹离线会显示错误并保留来源，合集里的不可用文件保留记录，重新连接后刷新即可恢复。视频库只保存位置，不复制或删除原视频；清除播放历史、清空播放列表和恢复设置均保留视频库。自定义合集保存本地文件和文件夹引用；添加文件夹后递归读取视频，刷新同步文件的新增与删除，重叠文件夹和单独添加的同一路径视频去重。空文件夹和离线文件夹保留，支持移除引用及重新定位，文件夹内扫描到的视频随目录管理；DLNA 以设备来源单独保留，临时播放和字幕地址不会写入保存记录。

本地文件夹、合集与 DLNA 来源复用文件夹行和目录导航，可逐级进入、返回上一级或回到根目录。本地文件夹与 DLNA 共享共用目录树，合集按文件路径的公共父目录组织层级，同一目录的合集保持平铺；自动推导的目录只展示包含视频的分支，显式加入的空文件夹和离线文件夹仍会显示；失效的合集成员仍可在对应目录内重新定位或移除。本地目录切换使用已加载的快照，刷新保留当前位置，目录消失后退回仍存在的上级。搜索和观看状态筛选覆盖当前本地目录及其子目录，清除搜索和筛选恢复文件树；本地库播放全部和追加包含当前范围内的子目录视频，保留搜索、筛选与排序结果。

视频库列表按可见行后台读取总时长和缩略图，使用独立静音解码器，避开黑屏片头，不改变当前播放进度。每个条目显示已播时间、总时长和百分比，并保留进度条；当前播放的视频每秒更新，未播放过的视频也能读取和缓存总时长，未知时长显示占位符。关闭历史记录后隐藏已保存的进度，仍显示总时长和当前视频的实时进度。预览缓存位于用户数据目录的 `thumbnails/`，以文件路径、大小和修改时间的哈希命名；内存保留最近 128 张，磁盘定期回收到 512 张。支持名称自然升序/降序、最近修改、文件大小和最近播放排序，以及未看、在看、已看、不可用筛选；本地库批量播放和追加仅作用于筛选后的可用视频。播放到 95% 或结束时记录为已看，重新播放不会丢失已看状态；可通过状态按钮或右键菜单手动标记，或恢复根据播放进度判断，手动标记保留续播位置。关闭播放历史后停止读取和写入观看状态，并停用对应筛选；清除最近历史保留观看记录。排序、筛选和自动刷新开关随偏好保存。

VR 拖动灵敏度支持 0.25–3×，默认 1×；移动后恢复居中的等待时间支持 0.25–5 秒，默认 1 秒。实验 AI 识别默认开启，关闭后继续使用元数据、画面规则和文件名识别；切换开关会重启当前视频的自动识别，保留手动类型选择。`FSVR_PROJECTION_MODEL=off` 仍可强制关闭模型。

快捷键页支持录入播放按键、冲突提示、单项及全部恢复默认，保留原有默认按键及别名。Escape 取消录入；系统和应用菜单组合不能分配给播放操作。自定义后立即生效并持久保存。

通用页的“外观”支持跟随系统、深色和浅色主题，默认深色。跟随系统时，系统外观变化会立即更新应用，无需重启；手动选择深色或浅色后保持该外观。切换立即应用到设置、视频库及播放列表、音量/倍速等浮层，并在下次启动时恢复；首页保留原有配色和海洋背景，顶部按钮和底部播放栏保留透明样式与原有配色，视频画布和字幕不受主题影响。

通用页的“历史”分别控制恢复播放进度、记录播放历史和启用最近打开菜单，三项默认开启。关闭历史记录会停止读取和写入续播及视频类型记录，保留已有记录；恢复进度和“播放 → 启动时打开上次视频”随之停用。最近打开总开关统一控制应用菜单、首页及系统提供的本应用最近项（包括 macOS Dock），实际播放过的本地视频均会加入最近列表。关闭开关会移除这些入口中的最近项并停止新增，应用旧列表保留供重新启用。

通用页提供清除播放历史和恢复默认设置，执行前使用原生确认对话框。清除历史只删除应用和系统最近文件列表（包括 macOS Dock 和 MyGo 最近文件缓存）以及启动恢复路径，保留续播进度、视频类型缓存和视频文件；当前播放及后续进度缓存继续工作，下次启动不会自动打开当前视频。恢复默认设置包括语言、音量、倍速及快捷键，保留播放历史和最近文件。

macOS Dock 图标右键菜单显示系统最近文件及“打开文件…”、“打开文件夹…”。启动时按应用历史恢复最近文件顺序，跳过已不存在的文件；点击最近文件会唤起窗口并播放，最小化时先恢复窗口。“文件 → 最近打开 → 清除最近文件”同时清除 Dock 历史。

同时支持普通 Flat 2D 和 VR 视频。新文件优先读取全景/立体元数据；没有空间元数据，或完整全景 + SBS 标签与 2:1 布局存在歧义时，在后台从视频前、中、后三段随机抽取画面，跳过黑屏与缺乏细节的帧。通常收集 3 个有效样本；证据不足时继续补帧，最多尝试 9 次，设置 12 秒超时。长视频优先读取随机位置附近的关键帧，重复时间戳会改用精确定位，避免稀疏关键帧一直停留在同一黑屏；短片直接精确抽帧。先做左右/上下眼局部视差匹配，再检查单目全景特征；近景匹配失败时扩大水平视差搜索，匹配门槛保持不变。结合鱼眼圆弧边界和全景接缝/极区特征做多帧投票；常规画面规则要求至少 2 帧且三分之二样本一致，模型与双目证据融合规则见下文文档。抽帧使用独立的静音解码器，AVC/H.264 的少量检测帧直接软件解码，HEVC 等格式保留硬件加速，不改变当前播放进度；主播放的 VideoToolbox 会话创建失败时直接回退软件，播放仍保持精确定位。

鱼眼通过可见镜头圆弧拟合识别，容忍局部水印、边缘噪声、偏心和部分裁边，不再要求固定圆外区域几乎全黑。明确的双圆或单圆鱼眼先于立体相似度判断；稳定的鱼眼边界证据不会被实验 AI 的其他类别分数覆盖。自动类型每次打开重新确认，手动选择继续保留。

画面和模型证据不足时保留文件名中的 VR180、VR360、SBS、TB、Mono、EQR、Fisheye/FE 等明确标记，没有标记则按 2D 播放，不单凭宽高比猜测。单目 180° 等距柱状图由模型辅助区分，低置信度时仍依赖元数据、名称或手动选择。不支持的空间格式（如左右 360°、立方体贴图）保留为 2D，可手动调整。底部“视频类型”菜单的手动选择优先，并随本地播放历史保存。自动结果单独保存在 `AutoProjection`，例如 `sbs_180_eqr`；手动切换不会覆盖它。没有手动选择时，加载立即采用自动缓存，再在后台重新检查；识别完成后更新自动缓存。点击“重新识别”会清除手动覆盖，等待期间保留当前构图与上次自动缓存。关闭模型时同样重新运行画面规则，不维护算法版本迁移缓存。换片、关闭视频、手动切换类型和退出会取消旧抽帧任务。

2D 视频独立等比适配窗口，留黑边，不分屏或执行 VR 人脸追踪；滚轮、捏合和缩放快捷键使用 2D 缩放，放大后拖动可平移，R 恢复完整画面。画中画按视频横竖比例创建。VR 保留原有旋转、纵深移动、分屏和人像居中设置；这些偏好仅作用于 VR，设置页始终可访问。

本地 MobileNetV3-Small 七分类实验当前默认启用，约 3.24MB 的权重随应用嵌入并通过现有 LiteRT 加载。模型与画面规则共用随机有效帧，常规路径至少两帧、平均最高分不低于 0.8 且领先第二名至少 0.15；明确鱼眼边界和手动选择优先。普通平均分不足时，可结合多帧高分预测与实际眼间对应确认双目；没有明确鱼眼边界的 SBS 鱼眼模型结果，以及与画面规则冲突的双目投影，至少抽取 9 帧再确认。`FSVR_PROJECTION_MODEL` 可覆盖权重路径，设为 `off` 可关闭模型作对照。完整融合规则、训练/验证方法和结果见 [doc/VIDEO_CLASSIFIER.md](doc/VIDEO_CLASSIFIER.md)。

双目是主要识别目标，单目作为辅助支持。多帧稳定的左右/上下对应证据不会被单目模型结果覆盖，双目内部仍允许模型细分 EQR 和鱼眼。`just video-samples` 生成七类及非标准鱼眼样本，输出到 `build/video-samples/`，双目、2D 对照和单目辅助组分别统计；非 180°、椭圆、裁边或满幅鱼眼统一按对应的 180° 鱼眼类型验证。

识别测试使用 `--recognition-test` 启动 flag；开发时可执行 `FSVR_RECOGNITION_TEST=1 just dev`。开启后每次打开视频都跳过历史自动/手动类型，并输出带任务编号的详细日志：空间标签、模型来源和 SHA-256、实际抽帧时间、黑屏跳过、左右眼相似度、逐帧及累计七类分数、投票与最终决策原因。可信标签的视频也会抽帧作诊断，最终仍保留原有标签优先级。测试结果不写回历史类型，续播位置照常保存；当次手动切换类型仍会取消正在运行的识别。已运行的新版实例也能接收另一次启动传来的 `--recognition-test`，没有文件参数时会重检当前视频。

DLNA 搜索由原生端分别绑定可用 Wi-Fi / 以太网接口的 IPv4 地址发送 SSDP 多播请求，避免 VPN 默认路由截走局域网发现；各接口并行搜索并合并去重，单个接口失败不影响其他接口。发现日志记录接口、响应数和结果数量。通过设备的 ContentDirectory 服务分页浏览目录，视频直接交给 FFmpeg 播放。无需运行 FSVR 服务，也不提供 FSVR 媒体库或密码登录。搜索设备会打开视频库，并将发现的设备作为来源保存在侧栏的 DLNA 分组；再次搜索更新设备地址并保留自定义名称。选择来源或刷新时先重新读取已知设备描述，无法连接则按设备身份重新发现；仅连接当前选择的来源，启动时不扫描所有设备。支持逐级浏览目录、返回上一级和根目录，目录按需分页加载，字幕支持设备声明的 CaptionInfoEx 和目录中的独立字幕文件。DLNA 的续播、视频类型、观看状态和缩略图按设备 ID 与媒体对象 ID 关联，播放地址变化后继续使用原记录；服务器提供的时长直接显示，文件大小用于排序，当前视频进度实时更新。离线或目录读取失败会显示错误并保留设备来源。播放列表只承载选择的视频，打开替换当前队列，追加保留当前选择和暂停状态，清空队列保留视频库来源。协议行为由模拟设备测试覆盖；本机已验证 Plex 的设备发现和根目录浏览，其他服务器及完整播放兼容性仍需实机验收。

每个本地文件夹或合集的顶部操作区都有独立的“DLNA”共享开关，开启时高亮，各库默认关闭，侧栏会标记已共享的库。开启后，同一局域网的电视、播放器或 VR 设备可发现 `Foursmith Player (电脑名称)`，浏览已开启共享的本地文件夹和合集并直接播放原视频。文件夹和合集使用与本地浏览相同的目录层级，共享时忽略失效文件和不含可用视频的分支，远程 DLNA 来源不转发。共享不依赖当前播放列表、搜索或观看状态筛选，也不改变本机播放。共享端用两个后台任务优先补齐正在浏览的视频信息，轻量读取容器头中的时长、分辨率和码率，复用本地缩略图的元数据缓存；目录请求不等待探测，文件替换后重新读取，关闭共享后丢弃未完成的结果。ContentDirectory 直接返回这些字段，支持只请求资源属性的筛选。原文件通过 HTTP Range 提供拖动进度，匹配的外部字幕通过 CaptionInfoEx 提供；不转码，格式和字幕能否播放取决于接收设备。共享面板显示设备名称与地址，各库的开关和设备身份随状态保存，下次启动自动恢复已开启共享的库，恢复通用设置保留这些选择。库的增删、重命名和重新定位立即更新共享，磁盘内容每 30 秒重新扫描，点击视频库刷新也会触发扫描。关闭某个库的共享会立即撤下该库并结束它的传输，其他库继续共享；全部关闭或退出应用时停止服务，关闭视频库窗口继续共享。SSDP 分别加入可用的 IPv4 局域网接口，并提供 ContentDirectory、ConnectionManager 和目录变更订阅；协议参考 [UPnP ContentDirectory:1](https://upnp.org/specs/av/UPnP-av-ContentDirectory-v1-Service.pdf) 与 [ConnectionManager:1](https://upnp.org/specs/av/UPnP-av-ConnectionManager-v1-Service.pdf)。自动化测试覆盖浏览、分页、字幕、Range、目录更新和停止；电视及 VR 设备发现与实际解码仍需实机验收。
