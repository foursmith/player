# Foursmith Player 原生版

Go + MyGo v0.7.4 原生 UI，FFmpeg 解封装、解码及导出，SDL3 音频输出。原生程序不嵌入浏览器，也不启动 Bun 服务。迁移工作区中的 `../web/` 保存原实现，作为界面、交互及算法对照；构建所需资源已收录本仓库，无需该目录。

```sh
brew install go just ffmpeg sdl3
just deps
just dev
just check
just test
just build
```

以上命令在本仓库根目录执行。构建产物位于 `build/darwin-arm64/Foursmith Player.app`。`just build` 收集本机 FFmpeg/SDL 的动态依赖和编码器，加入 LiteRT C 运行库，再重新执行本机临时签名。正式分发仍需开发者证书签名和公证。

图标、模型和三语文案由原生项目的 `assets/` 独立维护，应用名称与版本读取 `mygo.json`。

仅在明确需要应用包时执行 `just build`，统一覆盖 `build/` 中对应平台的现有产物，不为每次修改另建测试包。日常开发使用已有开发实例及相关检查、测试；若固定目录中的应用正在运行，先处理运行占用，不另建输出目录。协作规则见 [AGENTS.md](AGENTS.md)。

macOS 使用 VideoToolbox + CVPixelBuffer + Metal，视频帧不经过 Go 的 RGBA 拷贝；仅检测缩略图和导出画面读回 CPU。Windows/Linux 代码保留 FFmpeg 硬件解码与 MyGo GPU 投影路径，但当前输出需经过 RGBA 上传，尚未实现 D3D11/VAAPI 纹理直接共享。当前本机验证平台为 macOS arm64。

Windows/Linux 需要本平台的 FFmpeg、SDL3 开发 SDK 与 LiteRT C 库，设置 `FSVR_TFLITE_LIBRARY` 后在目标系统执行相同的 `just build`。Windows 打包从编码器、LiteRT 所在目录及可选的 `FSVR_NATIVE_LIB_DIR` 收集 DLL；Linux 需要 `patchelf`，按 `ldd` 收集非 glibc 依赖。非 macOS 的导出字幕使用 FFmpeg/libass，所用 FFmpeg 必须包含 `ass` 滤镜。跨平台代码与打包流程尚未做其他系统的实机验收。

`just doctor` 检查媒体依赖和 GPU。`FSVR_TFLITE_LIBRARY` 可指定兼容的 TensorFlow Lite C 运行库。开发时需要 FFmpeg 与 SDL3 头文件和动态库；macOS 自动读取 Homebrew 路径，其他平台使用 `CGO_CFLAGS` / `CGO_LDFLAGS` 指定工具链。

设置、最近文件和播放历史保存在系统用户数据目录中的 `Foursmith Player/state.json`，只读取当前应用的数据目录。macOS 最近文件同时通过 MyGo 同步到系统，供 Dock 菜单显示；MyGo 在同一用户数据目录维护 `recent-documents.json`。`--data-dir` 可隔离开发配置；文件或文件夹可直接作为启动参数。本地播放历史按完整路径、大小和修改时间识别文件。

打开文件、文件夹或拖入视频会替换本地播放列表，并立即播放新选择；播放列表底部的“添加”只追加文件，保留当前播放或暂停状态。原生“文件”菜单提供打开、最近文件、添加、关闭视频和 DLNA 搜索。macOS 使用 ⌘O 打开文件、⇧⌘O 打开文件夹、⇧⌘A 添加文件、⌘, 打开设置；Windows/Linux 使用 Ctrl。续播设置适用于本地文件，关闭视频会保存进度并停止下次启动时自动打开该文件。

macOS Dock 图标右键菜单显示系统最近文件及“打开文件…”、“打开文件夹…”。启动时按应用历史恢复最近文件顺序，跳过已不存在的文件；点击最近文件会唤起窗口并播放，最小化时先恢复窗口。“文件 → 最近打开 → 清除最近文件”同时清除 Dock 历史。

同时支持普通 Flat 2D 和 VR 视频。新文件优先读取全景/立体元数据；没有空间元数据，或完整全景 + SBS 标签与 2:1 布局存在歧义时，在后台从视频前、中、后三段随机抽取画面，跳过黑屏与缺乏细节的帧。通常收集 3 个有效样本；证据不足时继续补帧，最多尝试 9 次，设置 12 秒超时。长视频优先读取随机位置附近的关键帧，重复时间戳会改用精确定位，避免稀疏关键帧一直停留在同一黑屏；短片直接精确抽帧。先做左右/上下眼局部视差匹配，再检查单目全景特征；近景匹配失败时扩大水平视差搜索，匹配门槛保持不变。结合鱼眼圆弧边界和全景接缝/极区特征做多帧投票；常规画面规则要求至少 2 帧且三分之二样本一致，模型与双目证据融合规则见下文文档。抽帧使用独立的静音解码器，AVC/H.264 的少量检测帧直接软件解码，HEVC 等格式保留硬件加速，不改变当前播放进度；主播放的 VideoToolbox 会话创建失败时直接回退软件，播放和导出仍保持精确定位。

鱼眼通过可见镜头圆弧拟合识别，容忍局部水印、边缘噪声、偏心和部分裁边，不再要求固定圆外区域几乎全黑。明确的双圆或单圆鱼眼先于立体相似度判断；稳定的鱼眼边界证据不会被实验 AI 的其他类别分数覆盖。自动类型每次打开重新确认，手动选择继续保留。

画面和模型证据不足时保留文件名中的 VR180、VR360、SBS、TB、Mono、EQR、Fisheye/FE 等明确标记，没有标记则按 2D 播放，不单凭宽高比猜测。单目 180° 等距柱状图由模型辅助区分，低置信度时仍依赖元数据、名称或手动选择。不支持的空间格式（如左右 360°、立方体贴图）保留为 2D，可手动调整。底部“视频类型”菜单的手动选择优先，并随本地播放历史保存。自动结果单独保存在 `AutoProjection`，例如 `sbs_180_eqr`；手动切换不会覆盖它。没有手动选择时，加载立即采用自动缓存，再在后台重新检查；识别完成后更新自动缓存。点击“重新识别”会清除手动覆盖，等待期间保留当前构图与上次自动缓存。关闭模型时同样重新运行画面规则，不维护算法版本迁移缓存。换片、关闭视频、手动切换类型和退出会取消旧抽帧任务。

2D 视频独立等比适配窗口，留黑边，不分屏或执行 VR 人脸追踪；滚轮、捏合和缩放快捷键使用 2D 缩放，放大后拖动可平移，R 恢复完整画面。画中画按视频横竖比例创建，AB 导出使用相同的 2D 构图。VR 保留原有旋转、纵深移动、分屏和人像居中设置；播放 2D 时隐藏这些专用设置。

本地 MobileNetV3-Small 七分类实验当前默认启用，约 3.24MB 的权重随应用嵌入并通过现有 LiteRT 加载。模型与画面规则共用随机有效帧，常规路径至少两帧、平均最高分不低于 0.8 且领先第二名至少 0.15；明确鱼眼边界和手动选择优先。普通平均分不足时，可结合多帧高分预测与实际眼间对应确认双目；没有明确鱼眼边界的 SBS 鱼眼模型结果，以及与画面规则冲突的双目投影，至少抽取 9 帧再确认。`FSVR_PROJECTION_MODEL` 可覆盖权重路径，设为 `off` 可关闭模型作对照。完整融合规则、训练/验证方法和结果见 [doc/VIDEO_CLASSIFIER.md](doc/VIDEO_CLASSIFIER.md)。

双目是主要识别目标，单目作为辅助支持。多帧稳定的左右/上下对应证据不会被单目模型结果覆盖，双目内部仍允许模型细分 EQR 和鱼眼。`just video-samples` 生成七类及非标准鱼眼样本，输出到 `build/video-samples/`，双目、2D 对照和单目辅助组分别统计；非 180°、椭圆、裁边或满幅鱼眼统一按对应的 180° 鱼眼类型验证。

识别测试使用 `--recognition-test` 启动 flag；开发时可执行 `FSVR_RECOGNITION_TEST=1 just dev`。开启后每次打开视频都跳过历史自动/手动类型，并输出带任务编号的详细日志：空间标签、模型来源和 SHA-256、实际抽帧时间、黑屏跳过、左右眼相似度、逐帧及累计七类分数、投票与最终决策原因。可信标签的视频也会抽帧作诊断，最终仍保留原有标签优先级。测试结果不写回历史类型，续播位置照常保存；当次手动切换类型仍会取消正在运行的识别。已运行的新版实例也能接收另一次启动传来的 `--recognition-test`，没有文件参数时会重检当前视频。

DLNA 搜索由原生端直接发送 IPv4 SSDP 请求，通过设备的 ContentDirectory 服务分页浏览目录，视频直接交给 FFmpeg 播放。无需运行 FSVR 服务，也不提供 FSVR 媒体库或密码登录。设备仅在点击搜索时发现，目录按需加载，字幕支持设备声明的 CaptionInfoEx 和目录中的独立字幕文件。真实设备兼容性仍需实机验收。
